# 对抗审查问题修复

Status: implemented

## 问题

2.0.0 的四路干净上下文审查识别了 33 项问题：3 项 P1、28 项 P2、2 项 P3。既有检查漏掉不可解码文件覆盖、越界打包、失败验收误完成、记录丢失和看板显示错误。以下对应表保留原编号、触发条件和验证方式，供后续回归核对。

## 决策

现行实现维持四态、6+2 与单 CLI，通过共同的 Markdown 和路径处理修复流转边界。完成门只接受唯一验收章节中的单张表；文件写入先确认来源与目标，迁移前后引用保持同一实际目标。看板本地与内联载入采用相同数据契约，保留检查点、完整正文与读取失败前的数据。

长期约束在移除检查点前承接到正文，部分取消保留已生效范围；规则分别归 [收尾](../../../skills/bw/references/close.md) 和 [链接核查](../../../skills/bw/references/archiving.md#流转后的链接核查)。原输入与验收证据保留，已有 191 份归档原文及清单封印与审查前快照一致。

| 位置 | 角色 | 当前实现 | 连带验证 |
|---|---|---|---|
| skills/bw/scripts/bw.py | CLI、记录解析与看板数据 | 安全边界、唯一验收表、链接、围栏、锚点 | 真实 CLI 与既有回归 |
| skills/bw/assets/board.html | 扫描与界面 | 完整数据、状态、导航、同步与失败呈现 | 共用夹具与隔离 Chrome |
| skills/bw/references/ | 工作流契约 | 长期约束承接、部分取消、无提案分支与授权判断 | 逐条路径核对及收尾演练 |
| tools/、README、bywork/implemented/ | 交付、评测与现行事实 | 文件检出、安装路径、对照输入、历史来源 | 临时安装、失败子进程与 Git 原文核对 |

## 备选方案

- 为每条反例增加专用分支能够局部修复，但会重复 Markdown 与路径逻辑；共同解析和标准化路径同时覆盖校验、流转与数据生成。
- 第三方 Markdown 解析器能覆盖更多语法；当前所需语法由标准库 CLI 和静态看板处理，两种载入方式通过同一批夹具核对。引入依赖需要有超出当前语法范围的实际需求。

## 验证环境与边界

- 看板交互：`node tools/test-bw-board.cjs "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"`，Chrome 157.0.8103.79，隔离配置与离线模式；没有脚本异常或注入执行。文件系统接口用相同夹具模拟；系统选择器、操作系统实际撤权及其他浏览器未验证。
- 契约演练按文档显式安排语义步骤，再运行真实 CLI，证明流程可执行；不代表模型会自主遵循。长期会话和压缩后的遵循率仍需实际使用观察，已有历史证据见[压缩观察](../testing/2026-11-20-compaction-observations.md)。
- A/B 驱动只验证调度、输入与退出码，没有发起付费模型评测；隔离安装验证文件与命令，没有验证真实宿主加载和远端发布。

## 收益和代价

修复保护已发现的写入、流转和阅读边界，保留原始证据与明确限制。两套看板解析实现需持续通过共享夹具；维护侧增加 Node.js 检查，实际交互另需本机 Chrome。任意 Markdown 扩展、全部 I/O 事务和并发不在当前保证内；既有失败可能保留双份原文的边界见[DSH 管理机制对照](../testing/2026-11-20-dsh-management-alignment.md)。
