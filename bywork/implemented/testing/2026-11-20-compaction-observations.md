# 技能重读与压缩后的实测边界

Status: implemented

## 问题

技能正文、入口描述和宿主指令有不同的上下文生命周期。迁移记录时，需要保留旧触发方案的失败证据及研究来源，避免把新架构当成已经验证的长期效果。

## 决策

长会话遵循率以真实会话原文验证，分别核对技能重读、检查点、脚本调用与最终回复。现行四态架构见 [工作流决定](../architecture/2026-11-20-workflow-v3-redesign.md)，以下是旧版观察，不据此判定新版仍有同一缺陷。

### 旧版观察及证据边界

- 1.0.3 的两场会话：旧交接记载正文未被折叠时，4/4 次回复有完整三段总结；正文被压缩成一句摘要后，后续共 10 次回复均无总结，并出现绕过完成脚本、手写 done 或旧字段的行为。同场位于宿主 system 层的 Ponytail 指令仍生效。CHANGELOG 另记录压缩后 0/3 的样本；本次迁移没有重新核对两个计数口径，不合并统计。
- 1.0.4 将 description 改为“软件开发工作流：做任何事之前，先调用它。”后，一场简单 UI 修改会话经历 3 次压缩，仅开头调用 bw 1 次，后续无重读、无脚本调用，最终也遗漏三段总结。这一反例说明入口描述本身未能在该样本中促成再入。
- 原文依据为 Git 提交 `f02de57f3c9da4870a03d69aa94716469bd9a9cc` 中的 `bywork/work/workflow-research-handover/index.md` 第 18–19 行，可用 `git show f02de57:bywork/work/workflow-research-handover/index.md` 复核。这里承接历史记录，没有重跑旧会话；旧交接的待办计划已经被新架构取代。

## 备选方案

只保留新版结构可以缩短迁移，但会丢失旧触发机制的失败证据与来源；因此承接独有事实，并把历史观察与现行决定互链。

## 收益和代价

后续评测能回到原始观察；版本差异、统计口径和未重跑范围保持显式。新架构跨压缩、跨任务与长期治理效果仍需独立实测。
