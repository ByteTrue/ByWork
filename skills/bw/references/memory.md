# 记忆（Memory）

适用：随时保留跨会话仍有用的决定、取舍和避坑理由，更新现行约束，或维护 `bywork/vision/index.md`。

## 何时保留

记录服务于未来判断：
- **往前看**：后人仅看产物无法还原的行为选择、边界与所有权。
- **往回看**：受限制而作的妥协，以及容易在清理时误删的非显然保证。
- **做减法**：决定删减或替换时，保留代价上限和需要重访的信号。

按未来作用决定是否记录，不按改动大小。产物已能完整表达、无独立取舍的细节无需另写；有价值的理由在当前上下文中落盘，不等事后凭记忆补写。

## 检索与分类

记录位于 `bywork/<状态>/<分类>/yyyy-mm-dd-topic.md`。分类按项目主题扩展，可复用：

| 分类 | 判断对象 |
|---|---|
| `feature` | 能力与可观察行为选择 |
| `bug-fix` | 缺陷、根因与防回归条件 |
| `simplification` | 不增加能力的删减、合并与收窄 |
| `architecture` | 产物结构、职责与核心边界 |
| `process` | 围绕产物的协作、工具与交付规则 |
| `testing` | 验证策略、依据与覆盖边界 |

不维护中心化 `INDEX.md`。定位记录有四条路径：
1. 从入口文件或模块说明的反向锚点进入；支持注释的源码可用 `// Note: <不变量>。见 bywork/implemented/<分类>/<文件名>.md`，由 `bw.py anchors` 体检。
2. 按状态与分类切片，先看 `implemented/` 与 `rejected/` 中的相关主题。
3. 按关键词检索活跃区：`rg --hidden --glob '!bywork/archived/**' "<关键词>" bywork/`。
4. 沿现行记录和模块文档的相对 Markdown 链接下钻；归档只在需要追溯历史时读取。

## 与产物一起维护

- **事实变、理由不变**：原地更新现行记录，与产物同批完成；用现在时写事实，不追加日期流水账。
- **决定或核心理由翻转**：另写决定，保留真实考虑过的备选与取舍，不把旧篇改成相反立场。
- **写新篇时当场审计**：检索同主题活跃记录，处理重复、部分替代与完全吸收；保留、删除和归档的唯一判据见 [旧记录治理](archiving.md)。
- **提出并推进工作**：用 [proposed 模板](../templates/proposed.md) 保存检查点与验收依据；已实施或被否决的结论按 [收尾](close.md) 流转。

## 每篇必须讲清的意思

1. 问题独立于选定方案成立，决定具体到可以行动，理由说明为什么选它。
2. 备选只写真实权衡过的方案：先写其最强理由，再写当前条件下放弃它的原因；没有真实备选时如实说明，不编造陪衬。
3. 同时写收益与代价；简化尤其要保留上限和重访条件。没有对照基线就陈述事实，不写相对改善。
4. 验证说明依据、实际覆盖和未证明的范围。替代旧篇时，这些义务与缺口同样需要承接，不能随过程记录一起清掉。

## 格式与自检

- `proposed/` 先保留模板中的检查点 frontmatter；其后的正文与其他活跃记录一样，以标题、空行、唯一的 `Status:`、空行开头。
- 首节是 `## 问题`；补充结构与契约放在 `## 提案` 或 `## 决策` 与 `## 备选方案` 之间。中英章节别名由脚本支持；文件名日期始终是首次提出日。
- 写后按 [写作与语义自检](writing.md) 核对内容，再运行 `python3 <bw-skill>/scripts/bw.py check --project .`。
