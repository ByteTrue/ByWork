# 旧记录的保留、替代与归档

适用：新决定影响旧记录，或主动整理现行知识。日常只处理本次触及的主题；较大整理也按主题逐组核对。

## 按未来作用决定去向

- **仍能约束当前工作：留在活跃区。** 独立的理由、所有权边界、否定性保证、保护底线、被否方案的重访条件、验证义务与具名覆盖缺口，都不能因记录久远或实现很小而丢掉。
- **部分替代：两篇保持活跃并互链。** 双方写清哪些内容已被替代、哪些仍有效；链接本身不能代替有效范围的说明。
- **完全吸收：先搬承重内容，再处理旧篇。** 将旧篇独有且仍成立的理由、备选、后果、约束、验证义务与覆盖缺口收进新篇，并核对实际产物已经符合新决定。仍有未承接的现行作用就不算完全吸收。
- **没有独立价值：删除。** 内容已由现行记录或产物充分表达、无需保留历史快照时，修完入站链接后删除。
- **只剩历史价值：归档。** 仅已实施记录可移入 `archived/`；归档记录不再作为现行规则。
- **不再推进的提案：先承接生效部分，再否决或删除。** 按 [收尾](close.md) 保存已落地且保留的事实，有防重犯价值的理由用 `bw.py reject` 留存，其余清理。已否决记录在重访条件仍适用时保持可检索，条件消失且无独立价值时删除。

## 执行归档

```bash
python3 <bw-skill>/scripts/bw.py archive <旧记录> --superseded-by <新记录> --project .
```

没有替代记录时省略 `--superseded-by`。命令只接收 `implemented/` 记录：先检查现有封印与目标，拒绝同名覆盖、损坏清单和无效替代目标，再移动正文、在 `Status:` 后插入归档日期、登记 SHA-256；除日期外保持原文字节。随后按下节核查入站链接。归档内部的历史链接与措辞保持原样。

## 流转后的链接核查

命令报告只扫描三个活跃状态目录中的 Markdown；项目说明、`vision/` 和源码可能另有引用。移动或删除后，按旧路径及文件名检索全项目（排除 `bywork/archived/`），核对每个引用的真实目标并修复，再运行 `bw.py anchors --project .` 检查源码锚点。归档正文中的历史链接保持原样。

## 冻结与基线

- `bw.py check` 比较归档文件与 `archived/manifest.json`，拒绝漏封、缺失或哈希不符；`check --write-manifest` 只在既有检查通过后补封新增文件。
- Git 项目还与 `HEAD` 中已提交的清单比较，旧条目只能保留。CI 应通过 `BW_ARCHIVE_BASE_REF` 指定可信比较基线；显式指定却不可读取时检查失败。
- 无 Git 或尚无提交时只做当前清单与文件的一致性检查，不能检测正文和清单被一起重写。首份清单进入可信基线后才有跨版本保护。
- 历史记录需要纠正时在活跃区说明，不重写封存正文与旧封印。

完成后运行 `python3 <bw-skill>/scripts/bw.py check --project .`。检查能验证结构与封印，记录是否仍有指导价值由真实产物和理由判断。
