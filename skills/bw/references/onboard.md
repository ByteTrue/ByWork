# 接入与初始化

适用：首次接入项目，或将已有工作区迁入四态结构。

## 初始化

1. 检查已有 `bywork/`；若含 `work/` 或 `memory/`，按下节迁移。`init` 只创建目录，会提示旧布局，不会判断或转换原记录。
2. 运行 `python3 <bw-skill>/scripts/bw.py init --project .`，创建或保留 `proposed/`、`implemented/`、`rejected/`、`archived/` 四个生命周期目录。现有文件保持原样。
3. 运行 `python3 <bw-skill>/scripts/bw.py check --project .`，通过后开始四态工作流。分类目录和记录按实际任务创建。
4. 告知用户创建或保留了哪些目录。可在宿主全局或项目指令文件中加入「做任何事之前，先读取 `bw` 技能」作为重读入口；它是否常驻取决于宿主，长期遵循仍需真实会话验证。

## 从 1.x 工作区迁移

更新技能包和迁移项目记录是两件事。旧记录仍存在时，四态检查会报告结构错误。

1. 保留可恢复原件（已有 Git 提交或 `bywork/` 外的备份），逐篇列出旧 `work/`、`memory/` 及关联附件，核对实际产物。
2. 未完成工作按 [提案模板](../templates/proposed.md) 转入 `proposed/<分类>/yyyy-mm-dd-topic.md`，承接检查点、原验收标准、证据与未决缺口。新增必填字段只填已知事实，不能把未知或失败改成通过。
3. 当前生效的长期判断按 [记忆](memory.md) 整理到 `implemented/`，明确否决且有重访价值的判断进入 `rejected/`。旧目录名和完成标签不能直接决定新状态；只剩历史作用的内容保留在原件中，是否纳入归档按 [旧记录治理](archiving.md) 判断。
4. 逐项核对原件都有去向，承接独有理由、约束、验证义务和覆盖缺口，并按 [链接核查](archiving.md#流转后的链接核查) 更新项目引用。附件可以继续引用可恢复原件中的实际路径。
5. 将旧 `work/`、`memory/` 移出 `bywork/`，保留备份。运行 `bw.py check --project .` 并核对当前事实；验证通过前保持原件可恢复，不以清空旧目录代替迁移。
