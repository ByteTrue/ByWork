# 实现

先按主题检索 `implemented/` 与 `rejected/` 的现行约束。有 `proposed/` 时按下列步骤推进；没有提案且涉及多处改动、单轮做不完或需要接续时，先转入 [方案](plan.md) 建立提案。其余单步工作直接对照原始要求完成并验证。

## 行动

1. **对齐检查点。** 读取当前 `proposed/` 文档并核对实际产物；在 frontmatter 中更新 `status: in_progress`、`current_unit` 与 `next_action`，正文保持 `Status: proposed`。
2. **单项闭环推进。** 每次只取 `## 验收标准` 表中**第一条结果不为 `通过` 的行**作为当前唯一工作单元：
   - 按 [实现经济性](economy.md) 完成该项所需的最小改动；
   - 立即按 [证明](prove.md) 从真实生效入口核验；
   - 将真实观察到的原始证据与结果（`通过` / `未通过` / `无法判定`）就地写回该行，再取下一行。不要批量做完后集中补写。
3. **处理变化与阻塞。**
   - 用户中途调整目标或方案时，先更新 `## 问题`、`## 提案` 与 `## 验收标准`，受影响的已验行重置为 `无法判定` 并记录待重新验证的范围；
   - 遇到外部依赖缺失或未决分叉无法继续时，将 frontmatter 的 `status` 写为 `blocked`，在 `proof_gap` 与 `next_action` 写清卡点和恢复条件并向用户汇报。

全部验收项均为 `通过` 后，转入 [收尾](close.md)。
