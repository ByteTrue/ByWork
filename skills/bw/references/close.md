# 收尾（Close）

适用：工作准备交付，或决定不再推进提案。

## 已完成且有长期价值

1. 核对验收表每行结果恰为 `通过`，有实际证据，`proof_gap` 为空。无法验证的验收项保持未完成；已接受且不属于本次验收范围的限制仍写在结论中。
2. 核对六个检查点字段，将 `must_hold` 等字段中仍有效的约束、理由与覆盖限制承接到正文，再清掉过程安排。正文改为当前成立的事实，保留决定理由、真实备选、后果与验证结论。此时仍保留 `proposed` 状态、检查点及验收表，供脚本核验。
3. 运行 `python3 <bw-skill>/scripts/bw.py complete <文件名或路径> --project .`。命令检查完成条件，删除 frontmatter，将状态与提案、验收、风险标题转换为现行记录格式，并移入 `implemented/`；保留证据正文，不替模型做语义改写。
4. 按 [旧记录治理中的链接核查](archiving.md#流转后的链接核查) 修复入站链接；若影响旧记录，同步处理保留、替代与归档。

## 不再推进且有避坑价值

若已有部分落地且继续生效，先按 [记忆](memory.md) 在 `implemented/` 保存这部分事实、有效范围、约束与证据；在原提案中链接它，说明只放弃哪些剩余范围。原验收表保持原样，未通过项不改成通过。

再运行 `python3 <bw-skill>/scripts/bw.py reject <文件名或路径> --reason "<一句话原因及否决范围>" --project .`。命令移除检查点、将头部改为 `Status: rejected — <原因>`，保留原提案与备选的语境，移入 `rejected/`。

## 无长期价值的过程记录

完成的纯执行记录在验收通过、无未决缺口且修完入站链接后删除。放弃且没有防重犯价值的提案，在承接仍生效的部分并核查入站链接后清理。

最后运行 `python3 <bw-skill>/scripts/bw.py check --project .`。流转命令拒绝错误生命周期和同名覆盖；检查通过只证明结构一致，不能代替对事实与证据的核对。
