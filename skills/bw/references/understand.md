# 理解

理解动作用于摸清现状、链路、结构或背景，给出来源明确的解释。纯解释请求以说明收束；已有修改授权时，在范围明确后继续推进，仅在缺少授权或必要的用户决策时等待。

## 行动

1. **先读现行约束。** 按主题检索 `bywork/implemented/` 与 `bywork/rejected/`（排除 `archived/`），确认当前生效的决定与已证伪的死胡同。
2. **沿真实链路核对。** 从实际入口出发，顺清触发条件、责任边界、状态流转与可观察输出。项目文档或历史摘要与当前实际产出不一致时，以当前实际产出为准并指出偏差。
3. **区分事实与推断。** 已核实的结论注明具体文件、位置或命令输出；尚未核实的部分显式标为推断或 `无法判定`，并给出下一步核实方式。

目标或取舍未定时转入 [澄清](clarify.md)；已有授权且目标明确时，直接切换到 [方案](plan.md) 或 [实现](implement.md)。
